# Промпты для участников — «Паттерны в массиве сессий»

Клинический путь: **8 основных промптов**. Плюс обязательный предварительный шаг
безопасности и блок «продвинутое/опционально». Каждый промпт — для копирования в Claude
Code в папке репозитория.

> **Главное правило приватности (произнести дважды):**
> **Терминал сам по себе ≠ локальный AI.** Дело не в окне терминала, а в том, *где считает
> модель*. У Claude Code файлы и команды — локальные, но **бэкенд настраиваемый**:
> - **Путь A — полностью локально (макс. приватность):** Claude Code → локальная модель
>   (Ollama / LM Studio через Anthropic-совместимый прокси). Данные НЕ покидают машину.
>   Цена — модель слабее; для серьёзного мульти-сессионного разбора часто недостаточно.
> - **Путь B — облако (сильный анализ):** Claude Code → API Anthropic (или ChatGPT/Claude.ai).
>   Рассуждение уходит в облако → **обязательно: локальная анонимизация → ручная проверка →
>   только потом папка, которую видит агент.**
>
> По умолчанию Claude Code = путь B. Для демо мы идём путём B и работаем ТОЛЬКО с
> `demo/green_anon_reviewed/`. Тезис: *локальные инструменты ≠ локальный инференс — выбирайте
> путь осознанно.*

Данные: `sessions-ru/client-a` (Марина) и `sessions-ru/client-b` (Игорь).
Эталоны (страховка на случай сбоя) — в `reference-outputs/`. Сверка с «ключом» —
`ANSWER-KEY.md` у каждого клиента («что заложено vs. что нашёл AI»). Данные синтетические —
это инструментальная демонстрация, **не клиническая валидация**.

## Обязательный формат вывода (для КАЖДОГО клинического промпта)

Любой анализ должен выдавать по каждому наблюдению строго эту структуру:

1. **Доказательство** — прямая цитата из транскрипта.
2. **Интерпретация** — что это *может* означать.
3. **Альтернатива** — чем ещё это можно объяснить.
4. **Уверенность** — высокая / средняя / низкая (НЕ проценты — они выглядят научно, но не
   калиброваны).
5. **Клиническое действие** — «вынести в супервизию / уточнить у клиента / проверить записи»
   (НЕ «сделайте X»).
6. **Граница** — без диагнозов, без оценки суицидального риска, без решений о лечении.

Добавляйте этот блок в конец каждого промпта:
```
Формат каждого наблюдения: Доказательство (цитата) → Интерпретация → Альтернатива →
Уверенность (высокая/средняя/низкая) → Клиническое действие → Граница.
Уверенность словами, не в процентах. Где контекста мало — понижай уверенность и отметь это.
```

## Шаг 0 — Сканирование границы безопасности (запускать ПЕРВЫМ, всегда)

**Зачем:** до любого анализа отделить материал, требующий ЧЕЛОВЕЧЕСКОГО протокола.
**Важно:** промпт НЕ оценивает риск — только сигнализирует «нужен человек».

```
Прочитай <файл сессии>. До любого анализа просканируй текст ТОЛЬКО на содержание, которое
требует остановить AI-анализ и перейти к человеческому клиническому протоколу: прямые или
косвенные признаки самоповреждения, угрозы другим, насилие, вопросы защиты
несовершеннолетних, судебно-правовые риски.
НЕ оценивай степень риска. НЕ делай выводов «безопасно». Верни ровно одно из:
- «Требуется человеческий протокол» + точная цитата(ы), или
- «Маркеров, требующих остановки, не обнаружено» (это НЕ означает «безопасно»).
```
**На сцене сказать:** отсутствие флага AI ничего не значит. AI не может «очистить» риск и не
может его понизить. Решение о риске — всегда за человеком.

## Основной клинический путь (8 промптов)

### 1. Локальная анонимизация + ручная проверка
**Демонстрирует:** удаление стандартных ПД ЛОКАЛЬНО, до облака.
**Данные:** `sessions-ru/client-a/session-01.md` (живой инструмент — Presidio + spaCy ru).

```
Прочитай sessions-ru/client-a/session-01.md. Замени все персональные данные на типизированные
плейсхолдеры: <ИМЯ>, <АДРЕС>, <ТЕЛЕФОН>, <EMAIL>, <ДАТА>, <ОРГАНИЗАЦИЯ>, <ВРАЧ>, <ПРЕПАРАT>,
<НОМЕР>. Сохрани в demo/green_anon_reviewed/session-01-anon.md. Выведи таблицу: что найдено,
тип, строка. Не удаляй клинический смысл — только идентификаторы.
```
**Сверка:** раздел PII в `client-a/ANSWER-KEY.md`. Затем — ручная проверка (промпт 2).

### 2. Квази-идентификаторы (red-team, упражнение для зала)
**Демонстрирует:** то, что не ловит ни одна модель — ответственность терапевта.

```
Прочитай анонимизированный файл. Теперь как «атакующий», который хочет вычислить клиента по
косвенным признакам: найди КВАЗИ-идентификаторы — комбинации (профессия + город + возраст),
уникальные жизненные детали, редкие конфигурации. Для каждого: почему это риск и как
переформулировать, сохранив клинический смысл.
```
**Тезис:** автоматика убирает ~90% стандартных ПД; опасны оставшиеся 10%.

### 3. DoT-анализ одной сессии (с обязательными цитатами)
**Демонстрирует:** прозрачный разбор (Chen, Lu & Wang, EMNLP-Findings 2023).
**Данные:** `sessions-ru/client-a/session-01.md`

```
Прочитай sessions-ru/client-a/session-01.md. Проанализируй высказывания КЛИЕНТА по фреймворку
Diagnosis of Thought (DoT):
ШАГ 1 — Субъективность: раздели на факты и интерпретации.
ШАГ 2 — Контрастивное рассуждение: аргументы ЗА и ПРОТИВ + альтернатива.
ШАГ 3 — Анализ схемы: глубинная схема за паттерном; тип искажения (Бек 1976 / Бёрнс 1980).
Только речь клиента. [+ обязательный формат вывода]
```
**Сверка:** доминирует катастрофизация (S1). Шаг 3 — «анализ схемы», не «классификация».

### 4. Аудит вывода (supported / inferred / unsupported) — анти-галлюцинация
**Демонстрирует:** дисциплину скепсиса. Запускать ПОСЛЕ любого аналитического промпта.

```
Проверь свой предыдущий отчёт. Для КАЖДОГО утверждения отметь:
- ПОДТВЕРЖДЕНО (есть прямая цитата),
- РАЗУМНЫЙ ВЫВОД (логично, но без прямой цитаты),
- НЕ ПОДТВЕРЖДЕНО (нет основания в тексте).
Удали или понизь все «не подтверждённые» утверждения. Покажи исправленную версию.
```
**Тезис:** каждый вывод требует проверки; результат = ваше суждение + данные модели.

### 5. Мульти-сессионный тренд искажений (+ эволюция тем)
**Демонстрирует:** главную ценность — динамику через 5 сессий.
**Данные:** все `sessions-ru/client-a/session-0*.md`

```
Прочитай все пять файлов sessions-ru/client-a/session-01..05.md. Для каждой сессии посчитай
частоту каждого типа искажения у клиента. Таблица: типы × С1..С5 + «Тренд» (↑/↓/→). Затем
кратко: какая тема доминирует в каждой сессии и как смещается фокус. Резюме: что снижается
(прогресс), что РАСТЁТ (возможное замещающее искажение), рекомендация на следующий блок.
```
**Сверка (ключ):** направление важнее точных чисел — катастрофизация снижается (↓↓),
**чтение мыслей растёт (↑ замещающий паттерн!)**, сверхобобщение снижается, долженствование
смешанное (→). Точные счётчики clear/borderline — в `client-a/ANSWER-KEY.md`; в живом запуске
числа варьируются, часть пограничных случаев спорна (это и показываем в проверке по ключу).
Темы: работа → отношения → самооценка.

### 6. Избегание и незавершённые темы
**Демонстрирует:** темы, которые всплывают и блокируются — слепая зона на слух.

```
Прочитай sessions-ru/client-a/session-01..05.md. Найди ТЕМЫ ИЗБЕГАНИЯ: темы, которые клиент
начинает, но затем уходит от них. Для каждой: все случаи с цитатами и номером сессии, паттерн
ухода, осторожная гипотеза, почему это зона избегания. Не интерпретируй за пределами текста.
```
**Сверка:** «отец» — 4 эскалирующих эпизода (S2 → S5), не разрешён. У Игоря — «брат».

### 7. Отслеживание домашних заданий (задано / проверено / выполнено)
**Демонстрирует:** «задано vs проверено» — частый разрыв.

```
Прочитай sessions-ru/client-a/session-01..05.md. Таблица ДЗ: [Сессия | Что задано | Проверено?
(да/нет/частично) | Где проверено | Выполнено?]. Особо отметь задания, которые ЗАДАНЫ, но НЕ
проверены позже. Для интерпретации последствий используй осторожную формулировку («может
ослаблять преемственность; стоит вынести в супервизию»), без причинных заявлений.
```
**Сверка (ключ):** эксперимент — проверка брошена в S3; круг поддержки — не проверен после S4.

### 8. Памятка самосупервизии CBT (приверженность протоколу)
**Демонстрирует:** структурный аудит собственной работы. (Длинно — показывать эталон.)
**Данные:** например, `sessions-ru/client-b/session-02.md`

```
Прочитай sessions-ru/client-b/session-02.md. Проверь наличие элементов CBT-протокола: повестка;
проверка настроения; мост; проверка ДЗ; сократический диалог (не лекция); работа с горячими
мыслями; эксперимент/план; новое ДЗ; обратная связь; резюме. Для каждого:
есть/нет/частично + цитата + качество. Общая приверженность: X/10. Затем 5 вопросов для
супервизии (НЕ рекомендаций по лечению). Инструмент рефлексии, не оценка личности.
```
**Сверка:** ловит ли пропуск проверки ДЗ (у Игоря — хронически). Эталон: `reference-outputs/11`.

## Продвинутое / опционально (в репозиторий, не на сцену)

- **Маркеры разрыва альянса** — *маркеры в тексте, возможно указывающие* на разрыв/восстановление
  (Bordin/WAI). НЕ измерение альянса (текст не видит невербалику). Эталон: `reference-outputs/09`.
- **Change talk vs sustain talk** (Игорь) — процессный маркер MI (Miller & Rollnick), не
  универсальный маркер исхода. Эталон: `reference-outputs/10`.
- **Кросс-клиентский анализ практики** — гипотеза о составе клиентов / смещении кодирования /
  внимании терапевта (НЕ факт о «слепых зонах»). Только как финальный скриншот. Эталон: `12`.
- **Анализ предвзятости/контекста** — «где культурный, языковой, социоэкономический контекст
  или пропущенные сессии могут изменить интерпретацию? Понизь уверенность, где контекста нет.»
- **Капстоун: промпт → навык** — техническое расширение, как туториал в репо, не на сцене.

## Другие модальности — ACT и психодинамика (та же сессия, другая линза)

Сильная идея: **один и тот же анонимизированный корпус, прочитанный через три линзы** —
CBT / ACT / психодинамика. AI как мульти-парадигмальный микроскоп. На сцене — опционально;
в репозитории — полноценно. Чем интерпретативнее модальность, тем НИЖЕ уверенность и тем
строже формат: только гипотезы для супервизии.

### A1. ACT: психологическая (не)гибкость (гексафлекс)
**Линза:** Hayes/Strosahl/Wilson — 6 процессов. Маркеры наблюдаемы в тексте.
**Данные:** все сессии одного клиента (Марина или Игорь).

```
Прочитай все сессии клиента. Проанализируй через модель психологической гибкости ACT.
Для каждого из 6 процессов найди текстовые маркеры с цитатами:
1. Когнитивное слияние (fusion) ↔ разделение (defusion) — слияние с мыслями-ярлыками.
2. Экспериенциальное избегание ↔ принятие — уход от внутреннего опыта.
3. Привязанность к концептуализированному «я» ↔ я-как-контекст.
4. Доминирование прошлого/будущего ↔ контакт с настоящим.
5. Неясность ценностей ↔ ясные ценности.
6. Бездействие/неработающие действия ↔ преданное действие.
Отдельно: движения К ценностям (towards) и ОТ (away) по сессиям — есть ли сдвиг?
[+ обязательный формат вывода; уверенность словами; это гипотезы, не оценка по AAQ-II]
```
**Что смотреть:** перфекционизм/избегание (Марина) и прокрастинация-как-away-move (Игорь)
читаются как негибкость; ищем сдвиг к ценностям и defusion к поздним сессиям.

### A2. Психодинамическая линза: паттерн отношений, защиты, перенос
**Линза:** CCRT (Luborsky) — Желание / Ответ другого / Ответ себя; защиты; перенос.
**ВНИМАНИЕ:** вывод по тексту без невербалики — крайне интерпретативен. Только низкая
уверенность, только гипотезы для супервизии. Никаких заявлений об «измерении».
**Данные:** все сессии одного клиента.

```
Прочитай все сессии клиента. Дай ОСТОРОЖНЫЙ психодинамический разбор как набор гипотез:
1. Повторяющийся паттерн отношений (CCRT): сформулируй ЖЕЛАНИЕ клиента, типичный ОТВЕТ
   ДРУГОГО (ожидаемый/воспринимаемый) и ОТВЕТ СЕБЯ — с цитатами по сессиям.
2. Защитные механизмы: какие маркеры (интеллектуализация, минимизация, избегание аффекта)
   и где. Цитаты.
3. Возможные намёки переноса/контрпереноса (чувства к терапевту, эхом повторяющие другую
   значимую фигуру). Помечай как слабые гипотезы.
4. Тема избегания (отец / брат) как защищённый материал: что может стоять за уходом от темы.
[+ обязательный формат вывода; уверенность НИЗКАЯ по умолчанию; всё — для супервизии]
```
**Что смотреть:** «отец» (Марина) и конкуренция с братом (Игорь) дают CCRT-паттерн;
интеллектуализация как защита. Подчеркнуть пределы текстового вывода.

## Этическая граница (скрипт, произнести вслух)

**AI — микроскоп, не клиницист. Он помогает изучать текст; он не несёт клиническую
ответственность.**

Для суицидального риска: **у AI нет права вето и нет права «очистки». Он не может сказать
«безопасно», не может понизить тревогу.** Не использовать для: оценки суицидального риска,
кризисных интервенций, диагностики без верификации, решений о лечении, работы с
несовершеннолетними/защиты, судебных заключений, случаев без действительного согласия — и
всего, что вы не готовы защитить клинически.

Без клиентских кризис-ботов. Без авто-эскалации/деэскалации. Без числовых «оценок риска».
